# API要件

バックエンドAPIの一覧と、複数のAPIに共通する決まりをまとめる。

- 日付は`YYYY-MM-DD`形式で扱う。
- ユーザーIDは文字列として扱う。

---

## 1. API一覧

### ユーザー・認証

| Method | Path | 認証・権限 | 用途 |
| --- | --- | --- | --- |
| POST | `/register/request` | なし | ユーザー登録申請 |
| POST | `/login` | なし | JWT発行 |
| GET | `/requests` | 管理者 | pendingの登録申請一覧 |
| POST | `/approve/request/{request_id}` | 管理者 | 登録申請の承認 |
| PUT | `/reject/request/{request_id}` | 管理者 | 登録申請の却下 |
| GET | `/users` | 管理者 | ユーザー一覧 |
| DELETE | `/user/{user_id}` | 管理者 | スタッフ削除 |

### シフト期間

| Method | Path | 認証・権限 | 用途 |
| --- | --- | --- | --- |
| GET | `/periods` | ログイン済み | 期間一覧・営業日取得 |
| GET | `/period` | ログイン済み | 現在のシフト期間・営業日取得 |
| PUT | `/period` | 管理者 | シフト期間・営業日登録 |

### シフト希望・確定シフト

| Method | Path | 認証・権限 | 用途 |
| --- | --- | --- | --- |
| GET | `/user/shift/requests` | ログイン済み | 自分の希望取得 |
| PUT | `/shift/request` | ログイン済み | 自分の希望一括登録 |
| GET | `/shift/requests` | 管理者 | 全スタッフの希望取得 |
| GET | `/shifts` | ログイン済み | 全体の確定シフト取得 |
| PUT | `/shift` | 管理者 | 確定シフト一括登録 |
| GET | `/user/shifts` | ログイン済み | 自分の確定シフト取得 |

### 権限

- 認証が必要なAPIは、Bearerトークンから現在のユーザーを特定する。
- 「管理者」のAPIをスタッフが直接呼び出した場合は403を返す。

## 2. 対象期間の指定

シフト関連の取得・一括登録APIは、クエリパラメータ`period_id`で対象期間を指定する。

未指定時に使う期間は次のとおり。

| API | 未指定時の期間 |
| --- | --- |
| 希望の本人取得・登録（`GET /user/shift/requests`、`PUT /shift/request`） | 終了日が最も遅い期間 |
| それ以外 | 日本時間の当日を含む期間 |

---

## 3. シフト期間API

### `GET /periods`

- 全期間を終了日の降順で返す。
- 各要素は`id`、`name`、`start`、`end`、`business_dates`を持つ。

### `GET /period`

- `period_id`を指定した期間を返す。
- 未指定時は当日を含む期間を返す。`latest=true`の場合は終了日が最も遅い期間を返す。
- `period_id`を優先する。
- 対象がない場合は404とする。
- `shift_version`を返す。これが確定シフトの取得時バージョンとなる（4章）。

### `PUT /period`

- `name`、`start`、`end`、`business_dates`を受け取り、新規登録する。
- 重複時は409で`detail.message`と`detail.periods`（重複期間一覧）を返す。
- 上書き承認後は、`overwrite_period_ids`に確認対象の全IDを追加して再送する。
- サーバーが再計算した対象IDと一致しない場合は、409で再確認を求める。

重複の判定と上書きのルールは[シフト期間のルール 2](./period.md)を参照。

## 4. 同時編集の検出（バージョン）

古い画面から保存して、他の人の更新を消してしまうことを防ぐ。

| 対象 | バージョンの単位 | 取得時のバージョン |
| --- | --- | --- |
| 確定シフト | 期間 | `GET /period`の`shift_version` |
| シフト希望 | 本人・期間 | 希望の本人取得API（`GET /user/shift/requests`）の`version` |

- `PUT /shift`と`PUT /shift/request`は、クエリ`expected_version`（0以上）が必須。
- 保存直前に照合し、不一致は409で変更せず返す。
- 成功時は新しい`version`を返す。
- バージョンは削除・挿入と同じトランザクション内で更新し、失敗時はバージョンもロールバックする。

画面側の動作は次のとおり。

- 409時は画面の編集内容を維持し、ユーザーが確認してから最新データを再読み込みする。
- 保存中は編集操作を無効化する。

---

## 5. トランザクション

- 期間設定・希望登録・確定シフト登録は、削除と挿入を同一トランザクションで行い、例外時にロールバックする。
- PostgreSQLのトランザクション単位のアドバイザリロックで、これらの更新操作を直列化する。
