# スタッフ向け要件

## 1. スタッフの責務

スタッフは、管理者が設定した期間内で出勤可能日と備考を提出し、店舗全体の確定シフトを確認する。

## 2. 画面とナビゲーション

スタッフの下部ナビゲーションは以下の3項目とする。

| 項目 | パス | 用途 |
| --- | --- | --- |
| シフト | `/staff/shifts` | 全体の確定シフト確認 |
| 希望提出 | `/staff/shift/requests` | 自分のシフト希望編集・提出 |
| その他 | `/staff/others` | ログアウト |

## 3. アカウント登録申請

### 入力項目

- ID
- ユーザー名
- パスワード
- 確認用パスワード

### 動作

- 未入力項目がある場合は送信しない。
- パスワードと確認用パスワードが一致しない場合は送信しない。
- `POST /register/request`へID、名前、パスワードを送信する。
- 申請成功後はログイン画面へ移動し、管理者の承認が必要であることを表示する。
- 承認前はログインできない。

## 4. ログイン

- IDとパスワードを`POST /login`へフォーム形式で送信する。
- 認証成功時はJWTとロールを保存し、`/staff/shifts`へ移動する。
- 認証失敗時はバックエンドのエラーメッセージを表示する。

## 5. シフト希望提出

### 初期取得

- `GET /period`で現在の期間と営業日を取得する。
- `GET /user/shift/requests`でログイン中スタッフの登録済み希望を取得する。
- シフト期間が未設定の場合は、受付中の期間がないことを表示する。

### 編集

- 営業日のみ希望対象として表示する。
- 日付ごとに出勤可能かを選択する。
- 選択した日には任意の備考を入力できる。
- 選択数を画面下部へ表示する。
- 日付選択または備考変更は未保存の変更として扱う。

### 提出

- 選択した日付と備考を`PUT /shift/request`へ配列で送信する。
- バックエンドはログイン中スタッフの対象期間内の既存希望を削除してから登録する。
- 何も選択せずに送信した場合は、対象期間内の希望を空に更新する。
- 成功時は未保存状態を解除し、中央モーダルへ成功メッセージを表示する。
- 未保存状態で別画面へ移動する場合は破棄確認を表示する。

## 6. 確定シフト確認

### 初期取得

- `GET /period`で現在の期間と営業日を取得する。
- `GET /shifts`で期間内の店舗全体の確定シフトを取得する。

### 表示

- 管理者画面と同じカレンダー形式で表示する。
- 営業日には、その日に出勤する全スタッフの名前を表示する。
- 備考がある場合は名前の下に`（備考）`形式で表示する。
- 休業日は「休」、確定メンバーがいない営業日は「未定」と表示する。
- スタッフは閲覧のみ可能で、カレンダーから編集できない。

## 7. ログアウト

- その他画面のログアウト項目は薄い赤背景と赤文字で表示する。
- 実行前に「ログアウトしますか？」と確認する。
- 承認された場合はJWTとロールを削除し、ログイン画面へ移動する。

## 8. 権限制約

スタッフは以下を実行できない。

- シフト期間・営業日の登録
- 全スタッフの希望一覧取得
- 確定シフトの登録・編集
- ユーザー一覧取得・削除
- 登録申請の承認・却下

該当APIを直接呼び出した場合は403を返す。
