# UI要件

## 1. 目的

本書は、シフト管理Webアプリの現行画面を基準に、各画面の大まかな構成、表示内容、操作を定義する。

操作の流れとデータの扱いは、[管理者要件](./admin.md)、[スタッフ要件](./staff.md)、[シフト期間のルール](./period.md)に書く。

---

## 2. 共通UI

### 2.1 基本構成

- スマートフォンでの利用を中心とした画面構成にする。
- 各画面の上部にページタイトルを表示する。
- ログイン後の主要画面には、画面下部へ固定したナビゲーションを表示する。
- 固定ナビゲーションや固定操作ボタンが、画面の内容と重ならないようにする。
- タップ対象は小さくなりすぎないようにする。
- 読み込み中、データなし、エラー、処理成功の状態を画面上で分かるようにする。

### 2.2 下部ナビゲーション

| ロール | 表示名 | 遷移先 |
| --- | --- | --- |
| 管理者 | シフト編集 | `/admin/shifts` |
| 管理者 | シフト期間 | `/admin/period` |
| 管理者 | その他 | `/admin/others` |
| スタッフ | シフト | `/staff/shifts` |
| スタッフ | 希望提出 | `/staff/shift/requests` |
| スタッフ | その他 | `/staff/others` |

### 2.3 共通の状態表示

- 読み込み中は、読み込み中であることを示す表示を行う。
- 表示するデータがない場合は、その理由や次に必要な操作を表示する。
- 読み込みに失敗した場合はエラー内容を表示し、再取得できる場合は「もう一度試す」ボタンを表示する。
- 入力エラーやAPIエラーは、対象画面内にメッセージを表示する。

### 2.4 処理成功ポップアップ

- シフト期間登録、確定シフト登録、シフト希望提出の成功時に表示する。
- 画面中央に表示し、処理が完了したことと、APIの成功メッセージを伝える。
- 表示中は背後の画面を操作できないようにする。
- ポップアップ下部の「戻る」ボタンを押すと閉じる。

### 2.5 確認ダイアログ

キャンセルした場合は処理せず、現在の画面に留まる。

| 操作 | 表示内容 |
| --- | --- |
| ログアウト | 「ログアウトしますか？」 |
| 登録申請の却下 | 対象者名を含めて確認する |
| スタッフ削除 | 対象者名を含めて確認する |
| 重複する期間があるシフト期間の保存 | 下記 |

シフト期間の重複確認

- 「期間が重複しているシフト期間が存在します。上書きしますか？」と表示する。
- 重複する既存期間の名称・開始日・終了日をすべて表示し、対象期間全体が新しい1件に置き換わることを説明する。
- 「対象期間のシフト希望は削除されます。確定シフトのデータは保持されます」と表示する。
- 「はい」「いいえ」を表示する。「いいえ」の場合は入力内容を保持する。

### 2.6 未保存変更の離脱警告

- 管理者のシフト編集画面とスタッフのシフト希望提出画面で、未保存の変更がある状態から別画面へ移動する場合に表示する。
- 期間の切り替えにも同じ警告を適用する。
- 警告文は次のとおりとする。

```text
画面を切り替えますか？
（編集中の内容は破棄されます）
```

- キャンセルした場合は画面に留まり、編集中の内容を保持する。
- 移動を承認した場合は、編集中の内容を破棄して遷移する。
- 再読み込みやタブを閉じる操作に対しても、未保存の変更がある場合はブラウザ標準の警告を表示する。
- 保存成功後は未保存状態を解除する。

## 3. シフトカレンダー

### 3.1 共通UI

構成

- シフト期間名と対象期間をカレンダー上部に表示する。
- 期間が複数月にまたがる場合は、月ごとに分けて縦に表示する。
- 曜日は日曜日から土曜日までの7列で表示する。
- 日曜日と土曜日は曜日を判別できる色で表示する。

日ごとの表示

| 状態 | 表示 |
| --- | --- |
| 休業日（`business_dates`に含まれない日） | 「休」 |
| 確定シフトがない営業日 | 「未定」 |
| 確定シフトがある営業日 | スタッフ名。備考がある場合は、スタッフ名の下に`（備考）`の形式で表示する |

- 人数が3人以下の日は薄い赤、5人以上の日は薄い黄色で表示する。
- 各日付をタップすると、その日のシフト詳細を確認できる（ボトムシート）。

スマートフォンでの表示

- 7列表示を維持し、横スクロールせず確認できるようにする。
- 内容を判別できる文字サイズ、余白、折り返し・省略を用いる。
- 長いスタッフ名や備考によって、カレンダー全体の幅が広がらないようにする。

### 3.2 ロールごとの違い

- 管理者は、シフトカレンダーから日付ごとのシフトを編集できる。
- スタッフは、日付ごとのシフト確認はできるが、編集はできない。

### 3.3 期間選択UI

どの期間を初期表示するか、選択後に何が切り替わるかは[シフト期間のルール 3・4](./period.md)に従う。ここでは見た目と操作を定める。

- カレンダー上部のシフト期間名をタップすると、期間の選択肢を表示する。
- 期間名は操作可能なボタンとして実装し、キーボードでも選択操作できるようにする。
- 選択肢にはシフト期間名と開始日〜終了日を表示し、現在選択中の期間を判別できるようにする。名称が未設定の場合は「名称未設定」と表示する。
- 選択後は、その期間の情報へカレンダーと期間表示を切り替える。
- 当日を含む期間がない場合は「現在のシフト期間はありません」と「期間を選択」を表示し、既存期間を手動で選べるようにする。
- 期間が1件もない場合はその旨を表示する。

## 4. 認証画面

### 4.1 ログイン画面

- 画面上部にアプリのロゴを表示する。
- ID入力欄、パスワード入力欄、ログインボタンを表示する。
- ログイン処理中は二重送信できないようにする。
- ログインに失敗した場合は、フォーム内にエラーメッセージを表示する。
- 新規登録画面へ移動する「新規登録はこちら」を表示する。
- 登録申請の送信後に戻ってきた場合は、申請を送信したことを表示する。

### 4.2 新規登録画面

- ID、ユーザーネーム、パスワード、確認用パスワードの入力欄を表示する。
- 「申請を送信」ボタンを表示する。
- 未入力やパスワード不一致がある場合は、フォーム内にエラーメッセージを表示する。
- 送信処理中は二重送信できないようにする。
- ログイン画面へ移動する「ログインへ戻る」を表示する。

## 5. 管理者画面

### 5.1 シフト編集画面

- ページタイトルは「シフト編集」とする。
- 画面上部に「希望を反映」ボタンを表示する。
- 対象期間のシフトをカレンダー（3章）で表示する。シフト期間名から編集対象期間を選択できる。
- 営業日を選択すると、その日のシフト編集画面を重ねて表示する。スマートフォンでは画面下部から開く形式にする。
- 日ごとの編集画面には、次の情報と操作を表示する。
  - 対象日
  - 希望人数
  - 選択中の人数
  - スタッフ一覧
  - スタッフごとの選択操作
  - スタッフごとの備考入力欄
  - 希望を提出しているスタッフの「希望あり」表示
  - 「この日の編集を完了」ボタン
- 画面下部に「シフトを登録」ボタンを固定表示する。
- シフト期間が未設定の場合は、期間設定が必要であることを表示する。

### 5.2 シフト期間設定画面

- ページタイトルは「シフト期間の設定」とする。
- 期間名、開始日、終了日の入力欄を表示する。
- 開始日と終了日を入力した場合は、対象期間の日付を一覧表示する。
- 対象期間の日付一覧は、月曜日始まりのカレンダー形式で表示する。
- 各日について「営業」と「休」を切り替えられるようにする。
- 新しい期間を指定した場合は、日曜日と水曜日を休業日の初期値とする。
- 選択中の営業日数と、期間内の全日数を表示する。
- 「この期間で保存」ボタンを表示する。
- 保存は新規期間の追加を基本とし、期間重複時だけ確認ダイアログ（2.5）を表示する。
- 保存成功時は処理成功ポップアップを表示する。

### 5.3 その他画面

- ページタイトルは「その他」とする。
- 次の項目を一覧表示する。
  - スタッフ管理
  - 登録申請
  - 使用方法
  - ログアウト
- 各項目には、内容が分かる短い説明を表示する。
- 各項目固有のアイコンは表示しない。
- ログアウト項目は薄い赤背景と赤文字で表示する。選択した場合は確認ダイアログを表示する。

### 5.4 スタッフ管理画面

- ページタイトルは「スタッフ管理」とする。
- 画面上部に「戻る」ボタンを表示し、「その他」画面へ戻れるようにする。
- 登録済みユーザーの名前、ID、権限を一覧表示する。
- 管理者以外のユーザーには「削除」ボタンを表示する。
- 削除前に確認ダイアログを表示する。
- 削除後は、完了メッセージを画面内に表示する。
- 登録済みユーザーがいない場合は、その旨を表示する。

### 5.5 登録申請画面

- ページタイトルは「登録申請」とする。
- 画面上部に「戻る」ボタンを表示し、「その他」画面へ戻れるようにする。
- 申請者名と申請IDを一覧表示する。
- 各申請に「却下」と「承認」ボタンを表示する。
- 却下前に確認ダイアログを表示する。
- 処理後は対象申請を一覧から取り除き、結果を画面内に表示する。
- 未処理の申請がない場合は「未処理の申請はありません」と表示する。

## 6. スタッフ画面

### 6.1 確定シフト画面

- ページタイトルは「確定シフト」とする。
- 確定した全スタッフのシフトをカレンダー（3章）で表示する。シフト期間名から他の期間を選択できる。
- 自分の出勤日だけでなく、同じ日に出勤する他のスタッフも表示する。
- 管理者のシフトカレンダーと同じ内容を表示するが、編集操作は表示しない。

### 6.2 シフト希望提出画面

- ページタイトルは「シフト希望」とする。
- 対象期間名、開始日、終了日を表示する。
- 期間名をタップすると、確定シフト画面と同じ形式の期間選択肢（3.3）を表示する。
- 営業日を日付ごとの一覧で表示する。
- 各日を選択または選択解除できるようにする。
- 選択した日には、時間帯などを入力できる任意の備考欄を表示する。
- 画面下部に選択中の日数と「希望を登録」ボタンを固定表示する。
- 登録処理中は二重送信できないようにする。
- 登録成功時は処理成功ポップアップを表示する。
- 受付中の期間がない場合は、管理者による設定を待つよう案内する。

### 6.3 その他画面

- ページタイトルは「その他」とする。
- 「使用方法」と「ログアウト」を表示する。
- ログアウト項目には「ログイン画面へ戻る」と説明を表示する。
- ログアウト項目は薄い赤背景と赤文字で表示する。選択した場合は確認ダイアログを表示する。

---

## 7. 認証と画面遷移

- 未ログイン状態で管理者画面またはスタッフ画面を開いた場合は、ログイン画面へ移動する。
- ログイン後は、管理者をシフト編集画面、スタッフを確定シフト画面へ移動する。
- 管理者とスタッフは、それぞれ許可された画面だけを表示できるようにする。
- 存在しないURLを開いた場合は、ログイン状態と権限に応じた初期画面へ移動する。
