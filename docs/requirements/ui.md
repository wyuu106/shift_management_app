# UI要件定義

## 1. 目的

本書は、シフト管理Webアプリの現行画面を基準に、各画面の大まかな構成、表示内容、操作を定義する。

---

## 2. 共通UI

### 2.1 基本構成

- スマートフォンでの利用を中心とした画面構成にする。
- 各画面の上部にページタイトルを表示する。
- ログイン後の主要画面には、画面下部へ固定したナビゲーションを表示する。
- 固定ナビゲーションや固定操作ボタンが、画面の内容と重ならないようにする。
- 読み込み中、データなし、エラー、処理成功の状態を画面上で分かるようにする。

### 2.2 管理者の下部ナビゲーション

| 表示名 | 遷移先 |
| --- | --- |
| シフト編集 | `/admin/shifts` |
| シフト期間 | `/admin/period` |
| その他 | `/admin/others` |

### 2.3 スタッフの下部ナビゲーション

| 表示名 | 遷移先 |
| --- | --- |
| シフト | `/staff/shifts` |
| 希望提出 | `/staff/shift/requests` |
| その他 | `/staff/others` |

### 2.4 共通の状態表示

- 読み込み中は、読み込み中であることを示す表示を行う。
- 表示するデータがない場合は、その理由や次に必要な操作を表示する。
- 読み込みに失敗した場合はエラー内容を表示し、再取得できる場合は「もう一度試す」ボタンを表示する。
- 入力エラーやAPIエラーは、対象画面内にメッセージを表示する。

### 2.5 処理成功ポップアップ

- シフト期間登録、シフト登録、シフト希望提出の成功時に表示する。
- 画面中央に表示し、処理が完了したことと結果メッセージを伝える。
- 表示中は背後の画面を操作できないようにする。
- ポップアップ下部の「戻る」ボタンを押すと閉じる。

### 2.6 確認ダイアログ

- ログアウト時は「ログアウトしますか？」と確認する。
- 登録申請の却下時は、対象者名を含めて確認する。
- スタッフ削除時は、対象者名を含めて確認する。
- キャンセルした場合は処理せず、現在の画面に留まる。

### 2.7 未保存変更の離脱警告

- 管理者のシフト編集画面とスタッフのシフト希望提出画面で、未保存の変更がある状態から別画面へ移動する場合に表示する。
- 警告文は次のとおりとする。

```text
画面を切り替えますか？
（編集中の内容は破棄されます）
```

- キャンセルした場合は画面に留まり、編集中の内容を保持する。
- 移動を承認した場合は、編集中の内容を破棄して遷移する。
- 再読み込みやタブを閉じる操作に対しても、未保存の変更がある場合はブラウザ標準の警告を表示する。

## 3. シフトカレンダー

### 共通UI

- シフト期間名と対象期間をカレンダー上部に表示する。
- 期間が複数月にまたがる場合は、月ごとに分けて縦に表示する。
- 曜日は日曜日から土曜日までの7列で表示する。
- `business_dates`に含まれない日は休業日として「休」と表示する。
- 営業日に確定シフトがない場合は「未定」と表示する。
- シフトがある場合はスタッフ名を表示する。
- 備考がある場合は、スタッフ名の下に`（備考）`の形式で表示する。
- スマートフォンでも7列表示を維持し、横スクロールせず確認できるようにする。
- 長いスタッフ名や備考によって、カレンダー全体の幅が広がらないようにする。
- 各日付をタップすることで、その日のシフト詳細が確認できる（ボトムシート）
- 人数が3人以下の日は薄い赤、5人以上の日は薄い黄色で表示する

### 管理者UI

管理者は、シフトカレンダーから日付ごとのシフトを編集可能とする。

### スタッフUI

スタッフは、日付ごとのシフト確認はできるが、編集はできないものとする。

## 4. 認証画面

### 4.1 ログイン画面

- 画面上部にアプリのロゴを表示する。
- ID入力欄、パスワード入力欄、ログインボタンを表示する。
- ログイン処理中は二重送信できないようにする。
- ログインに失敗した場合は、フォーム内にエラーメッセージを表示する。
- 新規登録画面へ移動する「新規登録はこちら」を表示する。
- 登録申請の送信後に戻ってきた場合は、申請を送信したことを表示する。

### 4.2 新規登録画面

- ID、ユーザーネーム、パスワード、確認用パスワードの入力欄を表示する。
- 「申請を送信」ボタンを表示する。
- 未入力やパスワード不一致がある場合は、フォーム内にエラーメッセージを表示する。
- 送信処理中は二重送信できないようにする。
- ログイン画面へ移動する「ログインへ戻る」を表示する。

## 5. 管理者画面

### 5.1 シフト編集画面

- ページタイトルは「シフト編集」とする。
- 画面上部に「希望を反映」ボタンを表示する。
- 登録対象期間のシフトをカレンダーで表示する。
- 営業日を選択すると、その日のシフト編集画面を重ねて表示する。
- 日ごとの編集画面には、次の情報と操作を表示する。
  - 対象日
  - 希望人数
  - 選択中の人数
  - スタッフ一覧
  - スタッフごとの選択操作
  - スタッフごとの備考入力欄
  - 希望を提出しているスタッフの「希望あり」表示
  - 「この日の編集を完了」ボタン
- スマートフォンでは、日ごとの編集画面を画面下部から開く形式にする。
- 画面下部に「シフトを登録」ボタンを固定表示する。
- シフト期間が未設定の場合は、期間設定が必要であることを表示する。

### 5.2 シフト期間設定画面

- ページタイトルは「シフト期間の設定」とする。
- 期間名、開始日、終了日の入力欄を表示する。
- 開始日と終了日を入力した場合は、対象期間の日付を一覧表示する。
- 対象期間の日付一覧は、月曜日始まりのカレンダー形式で表示する。
- 各日について「営業」と「休」を切り替えられるようにする。
- 新しい期間を指定した場合は、日曜日と水曜日を休業日の初期値とする。
- 選択中の営業日数と、期間内の全日数を表示する。
- 「この期間で保存」ボタンを表示する。
- 保存成功時は処理成功ポップアップを表示する。

### 5.3 その他画面

- ページタイトルは「その他」とする。
- 次の項目を一覧表示する。
  - スタッフ管理
  - 登録申請
  - ログアウト
- 各項目には、内容が分かる短い説明を表示する。
- 各項目固有のアイコンは表示しない。
- ログアウトを選択した場合は確認ダイアログを表示する。

### 5.4 スタッフ管理画面

- ページタイトルは「スタッフ管理」とする。
- 画面上部に「戻る」ボタンを表示し、「その他」画面へ戻れるようにする。
- 登録済みユーザーの名前、ID、権限を一覧表示する。
- 管理者以外のユーザーには「削除」ボタンを表示する。
- 削除前に確認ダイアログを表示する。
- 削除後は、完了メッセージを画面内に表示する。
- 登録済みユーザーがいない場合は、その旨を表示する。

### 5.5 登録申請画面

- ページタイトルは「登録申請」とする。
- 画面上部に「戻る」ボタンを表示し、「その他」画面へ戻れるようにする。
- 申請者名と申請IDを一覧表示する。
- 各申請に「却下」と「承認」ボタンを表示する。
- 却下前に確認ダイアログを表示する。
- 処理後は対象申請を一覧から取り除き、結果を画面内に表示する。
- 未処理の申請がない場合は「未処理の申請はありません」と表示する。

---

## 6. スタッフ画面

### 6.1 確定シフト画面

- ページタイトルは「確定シフト」とする。
- 確定した全スタッフのシフトをカレンダーで表示する。
- 自分の出勤日だけでなく、同じ日に出勤する他のスタッフも表示する。
- 管理者のシフトカレンダーと同じ内容を表示するが、編集操作は表示しない。
- シフト期間が未設定の場合は、管理者による設定を待つよう案内する。

### 6.2 シフト希望提出画面

- ページタイトルは「シフト希望」とする。
- 対象期間名、開始日、終了日を表示する。
- 営業日を日付ごとの一覧で表示する。
- 各日を選択または選択解除できるようにする。
- 選択した日には、時間帯などを入力できる任意の備考欄を表示する。
- 画面下部に選択中の日数と「希望を登録」ボタンを固定表示する。
- 登録処理中は二重送信できないようにする。
- 登録成功時は処理成功ポップアップを表示する。
- 受付中の期間がない場合は、管理者による設定を待つよう案内する。

### 6.3 その他画面

- ページタイトルは「その他」とする。
- 「ログアウト」を表示する。
- ログアウト項目には「ログイン画面へ戻る」と説明を表示する。
- ログアウトを選択した場合は確認ダイアログを表示する。

---

## 7. 認証と画面遷移

- 未ログイン状態で管理者画面またはスタッフ画面を開いた場合は、ログイン画面へ移動する。
- ログイン後は、管理者をシフト編集画面、スタッフを確定シフト画面へ移動する。
- 管理者とスタッフは、それぞれ許可された画面だけを表示できるようにする。
- 存在しないURLを開いた場合は、ログイン状態と権限に応じた初期画面へ移動する。
