# シフト期間のルール

シフト期間と営業日、期間の重複、画面ごとの表示期間についてのルールをまとめる。管理者・スタッフの両方の画面に関わるため、この文書を正とする。

- 画面の見た目: [UI要件](./ui.md)
- APIの入出力: [API要件](./api.md)

---

## 1. 期間と営業日

- シフト期間は複数件保持する。
- 期間は名称、開始日、終了日、営業日の一覧を持つ。名称は任意。
- 開始日は終了日より前でなければならない。
- 営業日は期間内の日付から選択する。1日以上必要。
- `business_dates`に含まれない期間内の日は休業日として扱い、カレンダーに「休」と表示する。
- 管理画面で新しい期間を指定したとき、日曜日と水曜日をデフォルトの休業日とする。管理者は日ごとに営業日・休業日を切り替えられる。

---

## 2. 期間の重複と上書き

### 2.1 重複の判定

- 重複は開始日・終了日を含めて判定する。新規開始日が既存終了日以前、かつ新規終了日が既存開始日以後の場合は重複とする。
- 重複しない新しい期間は、既存期間を残して追加する。新規作成時に既存の`shift_periods`と`business_dates`を一律に削除しない。
- 重複判定と保存直前の再確認はバックエンドで行う。確認対象が変わった場合は再確認を求める。

### 2.2 確認

- 重複する期間がある場合は、対象期間の名称・開始日・終了日をすべて表示して、上書きするかを確認する。文言は[UI要件 2.5](./ui.md)を参照。
- 「はい」を選択した場合は、2.3のとおり置き換える。
- 「いいえ」を選択した場合は保存せず、既存データと入力内容を維持する。

### 2.3 上書きしたときに起こること

| 対象 | 扱い |
| --- | --- |
| 新しい期間と重複する既存期間 | すべて、その営業日とともに削除する |
| 新しい期間 | 営業日とともに1件として登録する |
| 重複しない既存期間 | 維持する |
| 置き換え対象の期間に属するシフト希望 | 全スタッフ分を削除する |
| 確定シフト | 削除・変更しない |

- 置き換えは既存期間全体を対象とする。新しい期間の外側にある部分も残さず、期間を分割しない。
- シフト希望の削除も、置き換え対象となる既存期間全体の日付範囲を対象とする。新しい期間の外側にある日付の希望も削除する。
- 確定シフトは、新しい期間の外側や、新たに休業日となる日付のものも、データとして保持する。
- 保持した確定シフトの画面表示は、選択中の期間と営業日の表示ルールに従う。「データが残ること」と「画面に表示されること」は区別する。
- 複数期間の削除と新規登録は1トランザクションで行い、失敗時は置き換え前の状態を維持する。

例: 既存期間が11月1日〜15日と11月16日〜30日、新しい期間が11月10日〜20日の場合。

- 承認後は新しい期間（11月10日〜20日）の1件だけになる。
- 11月1日〜9日と21日〜30日の期間は残さない。
- 11月1日〜30日のシフト希望は全スタッフ分を削除する。確定シフトは残る。

### 2.4 確定シフト登録との違い

- 確定シフト登録は、対象期間内の既存シフトを削除してから一括登録する。
- これは期間設定時の「確定シフトを保持する」ルールとは別の操作として扱う。

## 3. 画面ごとの初期表示期間

| 画面 | 初期表示する期間 |
| --- | --- |
| 管理者のシフト編集（管理者のホーム） | 日本時間の当日を含む期間 |
| スタッフの確定シフト（スタッフのホーム） | 日本時間の当日を含む期間 |
| スタッフのシフト希望提出 | 終了日が最も遅い期間 |

ホームは、ログイン後に最初に表示するシフト画面を指す。

### 3.1 当日を含む期間（ホーム）

- 現在日時から日本時間（`Asia/Tokyo`）の当日を求め、`開始日 <= 当日 <= 終了日`を満たす期間を表示する。
- 現在日時の判定基準はバックエンドとし、端末のタイムゾーンによって表示期間が変わらないようにする。
- 該当期間がない場合は「現在のシフト期間はありません」と表示する。過去・未来の期間を自動で代わりに表示しない。
- 未来の期間を新規作成しても、ホームは当日を含む期間を表示する。

### 3.2 終了日が最も遅い期間（希望提出）

- 登録済み期間のうち、終了日が最も遅い期間を表示する。
- 「最新」は作成日時や更新日時、今日の日付ではなく、期間に含まれる最も先の日付で判定する。
- 期間が1件もない場合は、希望提出できる期間がないことを表示する。

### 3.3 再判定のタイミング

- 画面を開いた時と再読み込み時に初期表示期間を判定する。
- 手動で選択した期間は、表示中に日付が変わっても自動で切り替えない。

## 4. 期間選択

3つの画面（管理者のシフト編集、スタッフの確定シフト、スタッフのシフト希望提出）で共通の操作とする。

- シフト期間名をタップすると、他のシフト期間の選択肢を表示する。
- 各選択肢には、シフト期間名と開始日〜終了日を表示する。期間名が未設定の場合は「名称未設定」と表示する。
- 過去・未来の期間も選択できる。
- 当日を含む期間がない場合も、「期間を選択」から既存期間を手動で選べるようにする。
- 期間が1件もない場合は、選択可能な期間がないことを表示する。

選択後の動作は画面ごとに異なる。

| 画面 | 切り替わる情報 | 編集・登録 |
| --- | --- | --- |
| 管理者のシフト編集 | 名称、開始日・終了日、営業日、確定シフト、シフト希望 | 選択中の期間だけを対象とし、他の期間のシフトに影響を与えない |
| スタッフの確定シフト | 名称、開始日・終了日、営業日、店舗全体の確定シフト | 閲覧のみ |
| スタッフのシフト希望提出 | 営業日、ログイン中スタッフの登録済み希望 | 提出は選択中の期間だけを対象とする |

- 取得・保存では、選択した期間の`period_id`を指定する（[API要件 2](./api.md)）。
- 未保存の変更がある場合は、期間切り替えにも破棄確認を適用する。キャンセルした場合は選択中の期間と編集内容を維持する（[UI要件 2.6](./ui.md)）。
